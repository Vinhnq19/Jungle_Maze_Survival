## 1. Mục tiêu

Khi gameplay xảy ra, người chơi thấy HUD **phản hồi** ngay trên khung đã duyệt của phần lõi, mà không che vùng giao tranh giữa màn hình. Sáu việc: (1) dải **tiến trình dùng đồ** thay dải vũ khí trong Quick bar, có trạng thái bắt đầu / hủy / xong; (2) hàng **hiệu ứng đang chịu** phía trên Vitals, có đồng hồ đếm ngược và biến mất khi hết hạn; (3) **thông báo nhặt đồ** ở góc phải dưới; (4) **hit marker** quanh tâm ngắm khi gây sát thương và **cung đỏ** trên vòng biên vùng giữa khi nhận sát thương; (5) **cảnh báo bom/bẫy** ở giữa trên (đồng hồ, hướng, khoảng cách) kèm **mũi tên** trên vòng biên khi nguồn nằm ngoài màn hình; (6) khi nhiều sự kiện cùng lúc, mỗi lớp vẫn đọc được nhờ giới hạn số phần tử, gộp, xếp hàng và tự ẩn. HUD **chỉ hiển thị** những gì ba nguồn dữ liệu (`HUDState`, `InventoryState`, `EffectState`) báo, không tự thay HP hay túi đồ, không tự suy ra vị trí đối thủ. Ticket gameplay thật (Game-10, ITM-01, WPN-02, WPN-01) chỉ cần đẩy dữ liệu vào cùng ba port mà không phải sửa bố cục.

## 2. Phạm vi và ranh giới

Nguyên tắc dùng nguồn (như phần lõi): **bố cục, vị trí, kích thước, màu, font lấy từ Figma v2; nội dung và số liệu lấy từ GDD; mâu thuẫn thì GDD thắng.** Canvas 1280×720, lề 24 px. Phần 2 **không sửa** khối nào của HUD lõi (`41:2`) ngoài hai điểm nối nhỏ ghi ở "Điểm nối với phần lõi".

**Trong phạm vi:**

1. **Tiến trình dùng đồ** (`48:374`, 411,572 · 458×32, thay dải vũ khí `41:116` khi đang dùng). Nội dung: "Đang dùng <displayName>" (132×18), thanh tiến trình 140×6 màu cam, giây còn lại (1 chữ số thập phân, vd "1.2s"), gợi ý hủy "Di chuyển để hủy" (xem Q21). Ba trạng thái: **Bắt đầu** (hiện dải, thanh chạy từ 0 tới đầy theo thời gian), **Hủy** (dải đổi thành "Đã hủy" màu mờ trong 0,6 s rồi trả dải vũ khí), **Xong** (thanh đầy, chữ "Xong" trong 0,25 s rồi trả dải vũ khí). Khe đang dùng đổi viền cam (xem AC-FB9).
2. **Hiệu ứng đang chịu** (`48:412`, 24,466 · cao 58, mọc sang phải). Mỗi `EffectChip` 44×58, bước 50 px (cách nhau 6 px): ô biểu tượng/nhãn 44×~40, thanh đồng hồ, giây còn lại dưới ô. Kiểu **bất lợi** viền/nhãn đỏ, kiểu **có lợi** viền/nhãn xanh lá. Tối đa 6 chip (6 chip rộng 294 px, mép phải x = 318, vẫn nằm ngoài vùng giữa sạch x ≥ 320). Đồng hồ đếm ngược, chớp khi sắp hết, biến mất khi hết hạn hoặc khi nguồn gỡ.
3. **Thông báo nhặt đồ** (`48:431`, 1115,564 · 141×132). Dòng `PickupToast` 31 px cao, bước 37 px, mới nhất ở dưới cùng, căn phải (mép phải x = 1256): dấu "+", ô icon 18×18 (placeholder, icon thật thuộc ART-04), tên món, `×n`. Tối đa 3 dòng; phần dư gộp thành chip "+n món khác" (`48:447`, 1164,564 · 92×21) ở trên cùng; dòng tự mờ dần rồi biến mất.
4. **Phản hồi sát thương.** (a) **Hit marker** (`48:459`, 56×56) bốn vạch trắng quanh tâm ngắm, chớp ngắn khi gây sát thương trúng. (b) **Hướng nhận sát thương**: cung đỏ đặc (`48:454`, 22×58) đặt trên **vòng biên** quanh vùng giữa sạch (hình chữ nhật tâm (640, 360), nửa cạnh 330 × 190, đặt theo góc thật, cách vùng giữa sạch 640×360 đúng 10 px; G1 chọn T-21 (a) thay elip), chỉ về phía nguồn, mờ dần.
5. **Cảnh báo bom/bẫy.** (a) **Banner** (`48:449`, 490,24 · 301×40, căn giữa ngang): "! Bom nổ sau 2s · hướng Tây Nam, 4 ô" trên nền đỏ nhạt, tự ẩn. (b) **Mũi tên ngoài màn hình** (`48:456`, 30×30 + nhãn giây `48:458`) đặt trên cùng vòng biên, kiểu **viền** (khác cung đặc của sát thương), chỉ khi nguồn cảnh báo nằm ngoài màn hình.
6. **Nhiều sự kiện cùng lúc:** mỗi lớp có giới hạn riêng (bảng "Giới hạn và thời gian" bên dưới), gộp sự kiện trùng, tự ẩn. Không lớp nào đổi vị trí hay kích thước khối của lớp khác hoặc khối lõi.
7. **Mở rộng ba port** `HUDState`, `InventoryState`, `EffectState` (bảng "Dữ liệu phần 2 cần") và **công cụ thử** trong Editor/Development build để bơm từng loại sự kiện (cách đo như AC16 của phần lõi).

**Hình ảnh tạm thời (người dùng quyết định 24/10/2026: "các phần UI chúng ta sẽ triển khai dùng AI render sau cứ làm tạm thời trước").** Phần 2 dùng hình **tạm**: màu phẳng theo style guide, ô giữ chỗ cho icon hiệu ứng và vật phẩm (ART-04 và bước AI render sau cấp icon thật), mũi tên/cung/hit marker vẽ đơn giản (hình học cơ bản). Các AC bên dưới chỉ đo **bố cục, hành vi, thời gian và dữ liệu**, không phụ thuộc vào hình ảnh cuối cùng. Việc cần kiểm lại khi có art thật nằm ở "Ghi chú kiểm lại khi có art thật" cuối mục 3 và **không chặn** nghiệm thu.

**Điểm nối với phần lõi** (hai sửa đổi nhỏ, tech-lead đưa vào kế hoạch):

- Dải vũ khí đang cầm (`41:116`) phải ẩn được khi có hành động dùng đồ và hiện lại khi hết (không đổi vị trí khi hiện lại).
- `Slot` thêm một trạng thái hiển thị "đang dùng" (viền cam) bên cạnh Default / Selected / Empty, không phá ba trạng thái cũ.

**Ngoài phạm vi (thuộc ticket khác):**

- Particle, số sát thương nổi, Hit Flash, rung màn hình, **viền đỏ toàn màn**, hiệu ứng thế giới (vùng nổ, vòng cảnh báo dưới đất) → VFX-01
- Logic hiệu ứng (áp Stun/Root/Slow/Poison/Tàng hình/Adrenaline/Thần dược, cộng dồn, hóa giải, thời lượng thật) → Game-10
- Logic nhặt, thay đồ, quản lý khe, trừ số lượng khi dùng, điều kiện hủy dùng đồ → ITM-01 (và Game-10 cho luật bị khống chế khi đang dùng)
- Tính sát thương, xác định ai trúng ai, gửi hướng sát thương → WPN-02; ném bom, ngòi, tạo bẫy → WPN-01
- Luật "ai được biết vị trí/hướng nguồn nguy hiểm" (tầm nhìn, LOS, âm thanh) → FOW-01 và Hero STT 13 (chưa chốt)
- Icon vũ khí/trang bị trong dòng nhặt và khe → ART-04
- Âm thanh phản hồi (hitmarker, tiếng nhặt, tiếng bom) → AUD-01 (WIREFRAME STT 11 đòi "hình + âm thanh", phần âm thanh không thuộc UI-01)

**Dữ liệu phần 2 cần mà phần lõi chưa có.** Phần lõi (theo mục 4 của `UI-01.md`, đã cập nhật 24/10/2026) có ba port đọc/ghi: `IHudState` (HP, giáp, mũ, vũ khí + đạn, trận, vị trí/hướng Hero), `IInventoryState` (4+4 khe, khe chọn), `IEffectState` (danh sách hiệu ứng, lõi chỉ dùng Adrenaline; `UI-01.md` ghi phần 2 thêm giá trị vào `EffectKind` mà không đổi port). Phần 2 mở rộng cùng ba port; các port này **chưa có trong code** lúc viết spec, nên cột "cổng" chỉ là gợi ý, tech-lead quyết. - **Không có nguồn dữ liệu song song.** Mọi dữ liệu phần 2 đi qua ba port của phần lõi, bằng cách **thêm** thành viên chứ không đổi thành viên cũ. Dữ liệu trạng thái (dùng đồ, hiệu ứng, cảnh báo) là thuộc tính đọc được kèm event báo đổi. Dữ liệu một lần (nhặt, gây sát thương, nhận sát thương) là event mang struct. Ghi qua port ghi, giống mọi chủ dữ liệu khác.
- **Event phần 2 tách khỏi `Changed` của phần lõi.** `HudPresenter.ApplyInventory` vẽ lại cả 8 khe với mọi cờ khác `None`. Nếu dùng một cờ `InventoryChange.UseAction` mới, mỗi sự kiện dùng đồ sẽ ghi lại 8 khe, và AC10 lõi ("không event thì không ghi view") dễ lệch. - **Đồng hồ đếm ngược nằm trong store, giống `EffectStateStore` của phần lõi.** `InventoryStateStore` đếm `RemainingSeconds` của hành động dùng đồ; `HudStateStore` đếm cảnh báo bom. Cả hai thành `ITickable` (Update), còn HUD đọc trong `LateUpdate` cùng frame. Ghi lại giá trị mới thì store lấy ngay giá trị đó, không nội suy (G-31, AC-FB46). Quy tắc hết giờ:

```csharp
// ---- Domain: Scripts/Domain/Hud/HudStateTypes.cs (sửa) ----
public enum EffectKind : byte { None = 0, Adrenaline = 1, Poison = 2, Slow = 3, Invisible = 4,
                                Stun = 5, Root = 6, Reverse = 7, CcImmune = 8 }   // giá trị cũ giữ nguyên

// ---- Domain: Scripts/Domain/Hud/HudFeedbackTypes.cs (mới), namespace JungleMaze.Domain.Hud ----
public enum EffectPolarity : byte { Harmful = 0, Beneficial = 1 }
public static class EffectKinds { EffectPolarity PolarityOf(EffectKind k); bool ShowsAsChip(EffectKind k); } // ShowsAsChip: false cho None, Adrenaline (Q22)
public enum ItemUsePhase : byte { Idle = 0, Using = 1, Cancelled = 2, Completed = 3 }
public readonly struct ItemUseStatus { ItemUsePhase Phase; string ItemId; string DisplayName; int SlotIndex;
                                       float TotalSeconds; float RemainingSeconds; bool Cancellable; }
public readonly struct ItemPickup { string ItemId; string DisplayName; int Count; }
public enum HitTargetKind : byte { Hero = 0, Other = 1 }
public readonly struct HitDealt { HitTargetKind Target; }
public readonly struct DamageTaken { bool HasDirection; float DirectionDegrees; }   // 0° = Đông, 90° = Bắc, ngược chiều kim đồng hồ
public enum DangerKind : byte { FusedBomb = 0, Trap = 1 }
public readonly struct DangerWarning { int Id; DangerKind Kind; float TotalSeconds; float RemainingSeconds; // Total 0 = không đồng hồ
                                       bool HasSource; float SourceX; float SourceY; bool IsTimed => TotalSeconds > 0f; }
public enum DangerChangeType : byte { Added = 0, Refreshed = 1, Removed = 2, Expired = 3 }
public readonly struct DangerChange { int Id; DangerChangeType Type; }

// ---- Domain (mới): DangerList.cs — như EffectList: mảng cố định Capacity = 16, khoá theo Id, Apply → Added/Refreshed,
//      Remove, Clear, Tick(dt, Action<int> onExpired) chỉ trừ mục có đồng hồ. Đầy thì bỏ qua (báo false).
// ---- Domain (mới): ItemUseTracker.cs — luật dùng đồ: Begin (cùng id đang Using = đồng bộ giây còn lại; khác id hoặc
//      đang không Using = bắt đầu mới, G-21), Cancel(id)/Complete(id) bỏ qua nếu id khác món đang Using (AC-FB12),
//      Tick(dt) kẹp tại 0, Reset → Idle. Trả về có đổi hay không.

// ---- Port đọc (thêm) ----
public interface IHudState   // + phần lõi
{
    event Action<ItemPickup> ItemPicked;
    event Action<HitDealt> HitDealt;
    event Action<DamageTaken> DamageTaken;
    event Action<DangerChange> DangerChanged;
    int DangerCount { get; }
    DangerWarning GetDangerAt(int index);         // thứ tự theo lúc thêm
}
public interface IInventoryState   // + phần lõi
{
    event Action<ItemUseStatus> UseChanged;       // Begin, đồng bộ, Cancel, Complete, Reset; không phát khi chỉ tick
    ItemUseStatus Use { get; }                    // RemainingSeconds đọc mỗi frame
}

// ---- Port ghi (thêm) ----
public interface IHudStateWriter   // + phần lõi
{
    void NotifyPickup(string itemId, int count);                        // ITM-01; count <= 0 hoặc id rỗng: bỏ qua; tên tra HudItemLabels
    void NotifyHitDealt(HitTargetKind target);                          // WPN-02
    void NotifyDamageTaken(bool hasDirection, float directionDegrees);  // WPN-02/FOW-01; NaN = không hướng
    void SetDanger(int id, DangerKind kind, float remainingSeconds,
                   bool hasSource, float sourceX, float sourceY);       // WPN-01; thêm hoặc làm mới; Trap bỏ qua remaining
    void ClearDanger(int id);                                           // nguồn gỡ
    // Reset() của lõi: xoá thêm mọi cảnh báo (phát Removed từng mục)
}
public interface IInventoryStateWriter   // + phần lõi
{
    void BeginUse(int slotIndex, string itemId, float totalSeconds, float remainingSeconds, bool cancellable); // ITM-01
    void CancelUse(string itemId);
    void CompleteUse(string itemId);
    // Reset() của lõi: Use về Idle (phát UseChanged)
}
// IEffectState / IEffectStateWriter: KHÔNG đổi chữ ký. Hiệu ứng mới chỉ là giá trị EffectKind mới;
// "không thời lượng" = Apply(kind, 0, 0) (đã hỗ trợ trong EffectList); làm mới = Apply lại (Refreshed).
```
